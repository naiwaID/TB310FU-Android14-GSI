# 联想「平板自助刷机工具」逆向分析

样本：`~/Downloads/平板自助刷机工具.exe`（40,100,384 B，MD5 `d595ce466ca7993264edc85ec08152be`）
分析日期：2026-11-04

---

## 一句话结论

这是一个 **MFC 写的壳 + 内置组件自解压** 的在线刷机器：它只做三件事——**按机型代码向联想服务器要一个 `.7z` 刷机包**，用 aria2 下载，解压后调内部工具刷写。
**服务器端机型白名单只有 44 个国内机型，没有 TB310FU / 启天K9**，所以这个工具对你的平板**无论怎么改都刷不了**——不是 SN 校验的问题，是压根没有这台机器的包。逆向到此的价值是：死心 + 确认正确路线（mtkclient 直连 BROM）。

## 2. 刷机流程（从字符串与调用点还原）

1. 读 `\TabletDriver.ini` 判断平台（`Tablet` / `Qualcomm` / `ROCKCHIP` / MTK）。
2. 驱动按平台从 CDN 现拉：

```
http://zsk-cdn.lenovows.com/GKPublic/Pad/Paddriver/MTKDriverSetup.7z
http://zsk-cdn.lenovows.com/GKPublic/Pad/Paddriver/Qualcomm.7z
http://zsk-cdn.lenovows.com/GKPublic/Pad/Paddriver/RK.7z
```

3. 取机型序列号/MTM → 向服务器查刷机包 → aria2 多线程下载 `.7z` → 7z.dll 解压 → 调内部工具按 `flashing_machine_method` 提示的按键进下载模式刷写。
4. 全流程会写日志 `\LenovoBrush.log`。

## 3. 服务端接口（关键发现）

三个端点，都在 `ptstpd.lenovo.com.cn`：

| 端点 | 用途 |
|---|---|
| `/home/ConfigurationQuery/getPadFlashingMachine` | **查刷机包**（核心） |
| `/home/ConfigurationQuery/getMachineSequenceInfo` | 查机器序列号信息 |
| `/home/ConfigurationQuery/uploadPadFlashingMachine` | 上传刷机统计 |

请求：`POST`，`Content-Type: application/json`，body 只一个字段：

```json
{"mtm":"机型代码"}
```

客户端本来带了 `Request-Id` / `Content-Md5` / `Timestamp` / `Sign-Data` 四个签名头（响应还用 RSA 公钥验签），**但实测服务端并不校验签名**，裸请求就返回数据。

返回字段：`product_name`、`product_model`、`market_name`、`latest_version`、
**`download_url`**（刷机包直链）、**`platform`**、**`flashing_machine_method`**（进下载模式的按键提示）、`if_ssg`、`diagram_type`。

`mtm` 是**模糊匹配**（`LIKE %关键词%`），所以 `{"mtm":"ZA"}` 就能拉出全表。

复现：

```bash
curl -s -X POST -H "Content-Type: application/json" \
  -d '{"mtm":"ZA"}' \
  https://ptstpd.lenovo.com.cn/home/ConfigurationQuery/getPadFlashingMachine
```

## 4. 白名单：44 个机型，没有 TB310FU

全表 44 条，覆盖 小新Pad / 拯救者Y700·Y900 / Yoga / 学习平板 系列：

```
SP-101FU  TB-128FU  TB-132FU  TB-138FC  TB-320FC  TB-331FC  TB-350FC  TB-350XC
TB-351FU  TB-370FC  TB-371FC  TB-372FC  TB-375FC  TB-520FU  TB-570FU  TB-9707F
TB-J606F  TB-J606N  TB-J607F  TB-J607Z  TB-J616F  TB-J616N  TB-J706F  TB-J706N
TB-J716F  TB-Q706F  TB-Q706Z  TB321FU  TB322FC  TB323FU  TB335FC  TB335ZC
TB365FC  TB376FC  TB378FC  TB522FU  TB710FU  TB711FU  YT-K606F  …（共 44）
```

- 搜 `TB310` → **0 条**；搜 `FU`、`X` 均正常返回，说明接口没问题，是**真的没收录这台机器**。
- 顺带确认：`TB-372FC 小新学习平板` 是有的，但那是另一台机器；**启天K9（TB310FU）不在里面**。

所以文章里"输入学习机 SN 后卡在解压 100%"——大概率是它拿到的是别的机型/驱动包在解压阶段的失败，或本地空间/权限问题；**改 SN、改注册表、改 MTM 都无解，服务端没有这个包**。

## 5. 对刷机的实际意义

1. **官方自助刷机工具这条路彻底堵死**，不用再折腾它（也不用装 Windows）。
2. 它的包结构（`Flash_tool_image/xxx_Tool.7z`、`platform: MTK`、`flashing_machine_method: 关机+音量键插线`）反过来印证了：**联想官方对 MTK 平板也是走"底层下载模式 + 分区写写"**，跟我们用 mtkclient 直连 BROM 是同一套原理。
3. 因此正确路线仍是：**mtkclient 解 BL + 关校验 → fastbootd 刷 GSI**，镜像用 Andy Yan 的 `lineage-21.0-20250621-UNOFFICIAL-arm64_bvN.img`（纯净无谷歌，比你文中作者那个 `bgN` 更干净）。

工具链已经在这台机器上备好：`~/tb310fu/`（mtkclient + venv + 6 个分步脚本），从 `bash ~/tb310fu/0-setup.sh` 开始。

# 把「智牛学习机」刷成 Android 14：联想启天K9（TB310FU）完整实战

> 一台锁死的英语学习平板，从"砖"到跑起 Evolution X 9.9.3（Android 14）。
> 全程在 Arch Linux 上完成，没有 Windows，没有付费工具。

---

## 一、这台机器是什么

| 项 | 参数 |
|---|---|
| 型号 | 联想 启天K9 / Lenovo Tab M9，**TB310FU** |
| SoC | MediaTek **MT6769V/CU**（Helio G80，MT6768 系列） |
| 存储 | 64 GB eMMC 5.1，**A/B 双槽**，`super` 分区 8192 MB |
| 屏幕 | 9" 1340×800 IPS，incell 全贴合 |
| 电池 | 5100 mAh，充电仅 **10 W（5V/2A）** |
| 原系统 | Android 12/13 + 智牛英语定制锁 |

先说结论：**这类机器不难刷，难的是它根本不该出现的"假死"**。

## 二、三个关键结论（省你几个小时）

### 1. 官方「平板自助刷机工具」用不了

那是个 MFC 壳 + 内置组件（`QuickFixTabletBrushTool.exe`、aria2 下载器、7z、各平台刷写 DLL），流程是：读 MTM → POST 到联想服务器查包 → 下载 `.7z` → 解压 → 调内部工具刷写。

核心接口：

```
POST https://ptstpd.lenovo.com.cn/home/ConfigurationQuery/getPadFlashingMachine
body: {"mtm":"..."}     ← 模糊匹配，{"mtm":"ZA"} 能拉出全表
```

返回里有 `download_url`、`platform`、`flashing_machine_method`。客户端本来带了签名头（`Request-Id`/`Sign-Data` 等），但**服务端不校验**，裸 curl 就能拿数据。

**但白名单只有 44 个国内机型，没有 TB310FU。** 所以改 SN、改 MTM、装驱动全都没用——服务端压根没这台机器的包。

### 2. 音量+ 和音量− 进的是两个不同的模式

这是最容易翻车的地方：

| 按键 | 进入的模式 | 用途 |
|---|---|---|
| **音量 +** | META / 工厂测试模式 | 产线自检 |
| **音量 −** | **Fastboot / Preloader** | SP Flash Tool、fastboot |
| **音量 + 按住 + 插 USB** | **BROM（0e8d:0003）** | **mtkclient 必须走这个** |

`mtkclient` 只能走 **BROM**。如果进了 `0e8d:2000`（Preloader），这台机器的 `DAA enabled: True` 会拒绝工具自带的未签名 DA，报：

```
Exploitation - Crashing da...
Preloader - upload_data failed with error: Unknown: 0x1d18
```

崩溃 preloader 也失败。**必须回到 BROM。**

### 3. 备份要一次跑完，中途拔线会让设备假死

这是本文最值钱的一段，我亲身踩了。

`mtkclient` 在读取分区时，会**主动关闭 SoC 的看门狗**（防止长操作被复位打断）。如果这时候拔线：

- 芯片停在 DA 模式里，等一条永远不来的 USB 命令
- 屏幕全黑（显示子系统从未初始化）
- 按键全部无响应（没有系统来处理按键中断）
- 插 USB 只有一瞬间的供电握手（扩展坞指示灯会闪一下）

**但它并没有坏。** `mtk r` 是只读操作，分区、引导、数据一个字节都没动。它只是停在了一个没人管的中间态。

## 三、怎么救回来

试过且**全部无效**的（别浪费时间）：

- 长按电源 10/20/30 秒
- 各种音量键组合
- 快速反复插拔充电器数百次（VBUS 抖动）
- 自制"深刷线"（USB 的 D+ 与 GND 之间串 1kΩ）
- 放着一夜等自然放电

**唯一有效：物理断开电池。**

拆后盖 → 拆下主板 → 电池排线断开（等价于硬断电）→ 30 秒后接回 → 用测试点开机。

主板上的测试点丝印很全，用万用表笔尖短接即可，不需要按实体键：

```
BAT+  BAT-  NTC  ID        ← 电池接口
VBUS  CC1  CC2  DM  DP     ← USB-C 接口
V+    V−   PWRK  SPK+  SPK−  GND
```

- `PWRK` ↔ `GND` 短接 1~2 秒 = 短按电源（**屏幕就亮了**）
- `PWRK` ↔ `GND` 保持 15 秒 = 强制关机
- `V−` ↔ `GND` 保持 + 插 USB = fastboot / preloader
- `V+` ↔ `GND` 保持 + 插 USB = **BROM**

我后来干脆焊了四根飞线出来，用颜色区分：

| 线色 | 测试点 | 作用 |
|---|---|---|
| 红 | GND | 公共地 |
| 橙 | V− | fastboot |
| 黄 | V+ | **BROM** |
| 绿 | PWRK | 开关机 |

## 四、完整刷机流程

### 环境

```bash
sudo pacman -S android-tools libusb     # fastboot + adb
git clone --depth 1 https://github.com/bkerler/mtkclient
python3 -m venv venv
./venv/bin/pip install pyusb colorama pyserial pycryptodome pycryptodomex capstone
```

（不需要 `requirements.txt` 里那一堆 PySide6/keystone，CLI 用不到。）

udev 规则：

```
SUBSYSTEM=="usb", ATTR{idVendor}=="0e8d", MODE="0666", TAG+="uaccess"
```

### 第 1 步：进 BROM，备份

关机 → 按住 **音量 +** → 插 USB（主板后置口，别用 hub）。

```bash
cd mtkclient
../venv/bin/python mtk.py printgpt
../venv/bin/python mtk.py r preloader preloader.bin --parttype boot1
../venv/bin/python mtk.py r vbmeta_a,vbmeta_b,vbmeta_system_a,vbmeta_vendor_a,boot_a,nvram,persist,seccfg \
    vbmeta_a.img,vbmeta_b.img,vbmeta_system_a.img,vbmeta_vendor_a.img,boot_a.img,nvram.img,persist.img,seccfg.img
```

**一定要一次跑完，别中途拔线。**

### 第 2 步：解锁 + 关校验

```bash
../venv/bin/python mtk.py multi "da seccfg unlock;e metadata,userdata,md_udc;da vbmeta 3;reset"
```

输出里看到 `Successfully patched vbmeta :)` 就对了。

### 第 3 步：进 fastboot

关机 → **音量 −** → 屏幕出现 START 菜单：

```
START
Press Volume Up/Down key for further MODE select
Volume Up: Enter Meta mode
Volume Down: Enter Fastboot mode
```

按**音量 −** 进 fastboot。

### 第 4 步：刷镜像

```bash
fastboot devices                      # 确认认到
fastboot --disable-verity --disable-verification flash vbmeta vbmeta_a.img
fastboot --disable-verity --disable-verification flash vbmeta_system vbmeta_system_a.img
fastboot --disable-verity --disable-verification flash vbmeta_vendor vbmeta_vendor_a.img
fastboot reboot fastboot              # 进 fastbootd（用户空间）
fastboot delete-logical-partition product_a
fastboot flash system gsi.img         # 2.6 GB，2~4 分钟
fastboot reboot
```

### 第 5 步：等

屏幕出现：

```
Orange State
Your device has been unlocked and can't be trusted
Your device will boot in 5 seconds
```

这是解锁成功的标志，不是错误。5 秒后进入开机动画，**首次启动 5~10 分钟**（deodex + 初始化）。

## 五、踩坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| `upload_data failed 0x1d18` | 进了 Preloader，DAA 拒绝未签名 DA | 改用音量+ 进 BROM |
| 备份后设备黑屏无反应 | 拔线导致 SoC 卡在 DA | 断电池 |
| `fastboot -w` 报 `partition not found` | `-w` 是 bootloader 命令，fastbootd 不支持 | 正常，数据在解锁时已清 |
| 刷完停在 Orange State | 正常 | 等 5 秒 |
| 卡开机动画超 15 分钟 | metadata 没清干净 | 进 fastbootd `fastboot erase metadata` 后重刷 |
| 触摸失灵 / IMEI 丢失 | 整包刷了跨区 ROW 固件 | **只刷 system**，别整包刷 |

**最后一条最重要**：GSI 方案只替换 `super` 里的 `system`，`vendor`、触摸固件、`lenovocust`（联想定制区）全都不动，天然避开"触摸失效"这个坑。整包刷 ROW 才会出事。

## 六、镜像选择

`arm64_bvN` 这个命名：

- `b` = A/B 双槽
- `v` = vanilla（无谷歌）
- `N` = 无 root

这台机器是 A/B，所以 `b` 对。镜像用的 Evolution X 9.9.3（Android 14，LineageOS 底子）。Andy Yan 的 LineageOS 21 GSI 也可以，但只发在 SourceForge，国内下载基本没速度；GitHub 上的包反而快。

## 七、代价

- 学习系统连同数据一起没了（解锁必清）
- 每次开机有 5 秒 Orange State 提示
- 拆机时碰掉了两个贴片元件，WiFi 挂了——**这是唯一的遗憾**，教训是拆机时镊子离板子远点
- 后盖是破坏性拆的，得自己做个壳

## 八、用 AI 辅助之前，先看这段

刷机这个领域，**AI 编造命令的概率高得离谱**，而且编得很像真的。我踩到了实锤：

```bash
python mtk.py emergency_recover      # 传说中的"紧急恢复"
python mtk.py --reset-preloader      # 传说中的"重置预加载器"
```

这两条在 2026 年的多篇中文教程里反复出现，写得有模有样，还配着"实测有效"。我去翻了本地 mtkclient 的源码和 `--help`：

```
$ ../venv/bin/python mtk.py --help | grep -i emergency
（无输出）
$ ../venv/bin/python mtk.py --help | grep -i reset-preloader
（无输出）
```

**两个命令都不存在。** 真实存在的只有 `crash`、`payload`、`meta`、`reset`、`e`（擦除）、`r`（读取）、`w`（写入）、`wl`（写逻辑分区）这几个。

这类幻觉为什么特别危险：设备已经变砖的时候，人是慌的，看到一个"一键紧急恢复"的命令会立刻照着敲。敲下去要么报错浪费一晚上，要么在错误的理解下继续折腾，把本来能救的机器搞成真砖。

**所以用 AI 辅助刷机，三条建议：**

1. **别用幻觉率高的模型**。这类任务需要精确的命令、精确的分区名、精确的错误码含义，模型一旦"顺手编一个"，代价是设备变砖。宁可换一个更保守的模型，也别图快。
2. **任何命令先验证再执行**。`mtk.py --help`、`fastboot --help`、`ls 路径`——三条命令就能挡住九成的幻觉。AI 给出一条你没见过的参数，第一反应应该是查帮助，不是敲下去。
3. **让它给出处**。问"这条命令在哪个版本、哪个文件里"，答不上来的直接丢掉。

想省事的话，本文配套的 `TB310FU刷机_AI提示词.md` 里已经把假命令列成黑名单了，整段贴给 AI，它会自己避开这些坑，也懂得一次只让人做一件事。

## 九、最后

这台机器的"黑屏死机"从头到尾就不是硬件故障，是**芯片卡在一个状态里**。理解这一点之后，一切就顺了：BROM 是入口，断电是唯一的重置手段，剩下的都是流程。

如果你也有一台锁死的 MTK 平板，先确认三件事：能不能进 BROM、有没有 preloader 备份、有没有 10 块钱的撬片。

有这三样，剩下只是时间问题。
